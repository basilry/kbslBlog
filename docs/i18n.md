# 한국어·영어 운영

공개 페이지는 `/ko`와 `/en` 아래에 있다. 예를 들어 같은 글은 `/ko/post/<slug>`와 `/en/post/<slug>`에서 읽는다. 언어 없는 기존 주소는 같은 경로와 검색 조건을 유지한 채 이동한다. 별도 API에 보관된 옛 숫자형 글 주소에는 현재 영어 번역이 없으므로 한국어 주소로 연결한다.

언어를 정하는 순서는 주소에 명시된 언어, 헤더에서 직접 선택해 저장한 언어, 접속 국가 순이다. Vercel의 `x-vercel-ip-country` 값이 `KR`이면 한국어를, 그 외 국가이거나 국가 정보를 확인할 수 없으면 영어를 사용한다. 브라우저의 언어 설정은 국가 기준을 대신하지 않는다. 수동 선택은 1년 동안 쿠키에 보관한다.

헤더의 언어 선택은 읽던 페이지와 검색 조건을 유지한다. JavaScript가 실행되면 주소의 앵커도 보존한다. JavaScript가 꺼진 경우에는 선택 후 `OK`를 누르면 된다. 정적 페이지의 JavaScript 없는 대체 폼에서는 검색 조건을 보존하지 못할 수 있다.

한국어 글은 `content/posts/*.md`, 영어 번역은 `content/posts/en/*.md`에 같은 파일명과 `slug`로 저장한다. 날짜, 카테고리, 원문 출처와 이미지 자산은 대응되는 원문과 맞춘다. 원문이 초안이거나 삭제되면 영어 파일이 있더라도 공개 목록과 검색에서 제외한다. 새 공개 글을 추가하거나 원문을 수정할 때는 영어 번역도 함께 반영한다. 번역 누락과 구조·출처 차이는 콘텐츠 테스트에서 확인한다.

검색 데이터는 언어별로 빌드할 때 생성하며 검색용 외부 API는 사용하지 않는다. RSS는 `/ko/feed.xml`, `/en/feed.xml`에서 제공하고 기존 `/feed.xml`은 한국어 구독 호환용으로 유지한다. 사이트맵과 페이지 메타데이터에는 언어별 주소와 대체 언어를 표시한다.

조회수는 언어 접두사를 제거한 기존 `/post/<slug>`를 키로 사용한다. 댓글도 Giscus의 기존 pathname 규칙과 같은 `post/<slug>`를 사용하므로 두 번역에서 같은 댓글을 공유한다. 언어를 바꾸어 페이지를 다시 열면 일반 재방문과 마찬가지로 열람 횟수가 증가한다.

공개 소개·프로젝트 데이터의 번역은 `src/lib/i18n/site-en.json`, 공통 화면 문구는 `src/lib/i18n/messages.ts`에서 관리한다. 원문 포트폴리오 데이터의 수치와 상태는 번역 과정에서 갱신하지 않는다.

확인 명령: `npm run lint`, `npm run typecheck`, `npm test -- --maxWorkers=1`, `npm run build`. 배포 전에는 한국·해외 기본 이동, 선택 쿠키, 글 6쌍의 HTML 언어·본문·정규 주소, 검색 데이터와 RSS, 기존 주소 연결을 함께 확인한다.

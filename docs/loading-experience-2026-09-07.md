# 페이지 전환 로딩 화면 복원 — 2026-09-07

본문 콘텐츠가 잠깐 사라지는 페이지 전환에서 헤더·푸터가 붙는 원인은 본문 높이를 `height: 100%`에 의존하면서 부모 높이가 확정되지 않았고, loading.tsx가 짧은 문단만 렌더링했기 때문입니다.

- 전체 레이아웃을 최소 100dvh의 세로 flex 구조로 변경하고 본문이 남은 높이를 채우도록 했습니다. 푸터는 로딩 중에도 화면 하단을 유지합니다.
- loading.tsx에 중앙 스피너와 로딩 안내를 추가했습니다. 보조기기 상태 안내와 reduced-motion을 지원합니다.
- 앞선 Next 업그레이드에서 제거했던 NProgress 본체와 스타일 연결을 복원했습니다. 실제 loading fallback의 표시·해제에 맞춰 상단 표시줄을 시작·종료합니다. 기존 Next 라우터 래퍼 패키지 전체를 되돌리지는 않았습니다.
- 중첩 fallback은 같은 표시줄을 공유하고 마지막 로딩이 끝났을 때만 종료합니다. 해제 함수는 중복 호출돼도 안전합니다.
- 짧은 화면에서 스크롤 위치 표시줄이 100%로 남지 않도록 맨 위에서는 0으로 표시합니다.

검증: 로컬 검사 페이지에서 헤더 상단·푸터 하단 유지, 중앙 스피너·NProgress 표시, 정상 페이지 이동 후 로딩 표시 해제를 시각 확인했습니다. 검사 페이지는 제거했습니다. 타입·ESLint 검사와 전체 테스트 28개를 통과했습니다. 로딩 진행 표시줄 수명 관리 회귀 테스트 2개를 포함합니다.

실제 다운로드 비율을 아는 표시줄은 아니며, 대기 중임을 나타내는 진행 표시입니다. 캐시된 페이지가 즉시 표시되면 별도 로딩 화면이 나타나지 않을 수 있습니다.

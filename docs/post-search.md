# API 서버가 필요 없는 포스팅 검색

검색 데이터는 `next build` 때 저장소의 공개 Markdown에서 만들고, 검색·정렬·카테고리 필터·페이지 이동은 브라우저에서 처리합니다. 검색을 위해 API 주소나 별도 서버를 설정할 필요가 없습니다.

## 데이터 흐름

1. `search-index.ts`의 `buildPostSearchIndex()`가 공개 글만 읽습니다. `draft: true`인 글은 직렬화 전에 제외합니다.
2. 빌드 중 Markdown을 해석하고 HTML을 제거하여 제목·설명·태그·날짜·카테고리·글 주소·본문 텍스트를 만듭니다.
3. `/search` 정적 페이지의 React 데이터에 검색 데이터를 포함합니다. 별도 API 엔드포인트는 만들지 않습니다.
4. `PostSearch.tsx`가 브라우저 URL의 `q`, `category`, `page`를 읽습니다.
5. 브라우저에서 실행되는 `search.ts`가 검색·관련도 정렬·카테고리별 건수·페이지 분할을 처리하고 기존 `PostList` 화면으로 표시합니다.

공개 글을 추가·수정·삭제하면 다시 빌드하고 배포해야 검색 데이터에도 반영됩니다. 이미 페이지를 열어 둔 방문자는 새로고침하면 새 배포의 검색 데이터를 받습니다. 본문 전체가 검색 데이터에 포함되므로 초안과 비공개 콘텐츠는 이 경로에 추가하지 않습니다.

## 검색과 탐색 규칙

- 검색 대상은 `content/posts`의 공개 Markdown 전체입니다. 과거 API의 숫자 글은 자동 수집하지 않습니다. 별도로 보관한 글을 검색하려면 먼저 공개 Markdown으로 가져와야 합니다.
- 제목·설명·태그·본문을 검색합니다. 공백으로 구분한 모든 단어가 포함된 글을 찾고, 대소문자는 구분하지 않습니다. 유니코드 표기를 정규화하며 검색어는 최대 100자입니다.
- 일치한 필드마다 제목 8점, 태그 4점, 설명 2점, 본문 1점을 더합니다. 같은 점수는 최신 발행일순입니다. 본문에서 일치하면 해당 위치 주변 최대 220자를 표시합니다.
- 검색 결과는 10개씩 보여 줍니다. 이전·다음과 현재/전체 페이지를 표시하고, 새 검색이나 카테고리 변경은 1페이지부터 시작합니다. 존재하지 않는 페이지 번호는 마지막 유효 페이지로 바로잡습니다.
- 검색어·카테고리·페이지는 URL에 유지합니다. 빈 검색어는 공개 글 전체를 보여 주고, 카테고리 숫자는 현재 검색어에 일치한 글 수입니다.
- 검색 결과 페이지는 `noindex, follow`, canonical은 `/search`입니다. 개별 검색어용 페이지를 빌드하거나 검색 엔진에 색인시키지 않습니다.
- 이전 글 API 호출·5분 API 캐시·1,000개 검색 상한은 사용하지 않습니다. 검색 데이터에 들어 있는 공개 글 전체를 검색합니다.

검색 페이지는 빌드 시 정적 생성하고 `useSearchParams`를 사용하는 클라이언트 컴포넌트를 `Suspense`로 감쌉니다. 파일 읽기와 HTML 해석 코드는 브라우저 검색 모듈과 분리합니다. 참고: [Next.js 정적 생성](https://nextjs.org/docs/app/guides/static-exports), [useSearchParams의 정적 렌더링](https://nextjs.org/docs/app/api-reference/functions/use-search-params).

이 변경은 검색 기능을 정적으로 만드는 범위입니다. 현재 저장소 전체에는 요청 시 실행하는 다른 경로와 이미지 프록시 등이 남아 있고, `next.config.js`에 `output: "export"`는 설정되어 있지 않습니다. 저장소 전체를 GitHub Pages로 이전하려면 별도 배포 호환성 작업이 필요합니다. 확인한 최근 커밋 `5991fa0`의 배포 상태는 Vercel 성공입니다.

검증에는 API 없이 검색 데이터 생성, 초안의 직렬화 제외, 검색 필드별 일치, 한글 정규화, 본문 문맥·HTML 제거, 1,250개 데이터에서의 검색·페이지 이동, URL 조건 유지가 포함됩니다.

## 최근 검색어

글 목록과 검색 결과의 검색창 아래에 최근 검색어를 최대 5개 표시합니다. 검색을 실행하거나 최근 검색어를 클릭했을 때만 기록하며, 같은 검색어는 중복으로 쌓지 않고 맨 앞으로 옮깁니다. 입력 중인 단어, 카테고리 변경, 페이지 이동은 기록하지 않습니다.

검색어는 현재 브라우저의 `localStorage`에 저장합니다. 개별 삭제와 전체 삭제를 지원하며, 전체 삭제도 이 기능의 저장 항목만 제거합니다. 다른 탭에서 기록을 바꾸면 함께 반영합니다. 브라우저가 저장소 사용을 차단한 경우 현재 페이지의 메모리에서 동작합니다. 최근 검색어 목록을 서버에 별도로 전송하지 않으며, 서버가 만드는 HTML에는 방문자의 검색 기록을 포함하지 않습니다. 실행한 검색어는 기존 검색 기능과 같이 URL의 `q`에 들어갑니다.

최근 검색어를 클릭하면 선택 중인 카테고리에서 해당 검색을 1페이지부터 실행합니다. 기록을 지운 뒤 새로고침하거나 검색 결과를 다시 방문해도 지운 항목을 자동으로 복원하지 않습니다.

## 상세 페이지의 이전 글과 다음 글

공개 Markdown 글의 본문 아래, 댓글 위에 이전 글·다음 글 카드를 표시합니다. 이전 글은 발행일이 더 오래된 글이고, 다음 글은 더 최근 글입니다. 같은 발행일은 slug 순서로 정렬해 이동 순서를 일정하게 유지합니다. 카드에는 제목과 발행일을 표시하고, 전체 글 보기 링크도 제공합니다.

초안은 이동 대상에서 제외합니다. 가장 오래된 글에는 이전 글 링크를, 가장 최근 글에는 다음 글 링크를 만들지 않으며 처음과 끝을 연결하지 않습니다. 별도 API가 필요한 과거 숫자 주소의 글은 이 목록에 포함하지 않습니다. 최근 검색어 저장·삭제·탭 간 반영·저장소 차단 처리와 글 이동의 양 끝·동일 발행일·초안 제외를 테스트합니다.
